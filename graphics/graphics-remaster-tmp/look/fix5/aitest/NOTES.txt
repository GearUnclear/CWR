2. Determinism and thread safety, again
---------------------------------------
Determinism: AI's medium reads only fog, rain, skyThrough, the sun's elevation and azimuth, night,
the date (synced or derived from the synced clock) and the knobs fogDensity and fogMist; its map
only the island's heights. No wall clock or frame counter enters (ComputeFogMedium and
FogSightTransmittanceThrough checked; AI's march (FogSightExtinctionAt, MistShape) does not read
mistNoise, so the drawn mist's banks are the shader's alone). Pinned by tests c and d. The in-game probe shows the
remaining drift in a run is the mission clock: Tai 0.9293 -> 0.9282 over 90 frames of 09:30.
Remaining per-machine inputs (unchanged from round 4): the debug knobs fogDensity and fogMist.
Also noted: the map is rebuilt when SampleHeights changes; for ranges over 64 it samples a
sparse diagonal pattern, so a single height edit off the pattern keeps the old map (the same rule
as the terrain horizon map, so the drawn floor and AI stay on one map).

Thread safety: unchanged verdict, safe today. BACKGROUND_AI is 0 (WorldInit.cpp 103): the
simulation step, PerformAI (Target.cpp) and the renderer all run on the main thread, and only
SimulateFogSight and ShutdownFogSight write the state. One hazard removed: FogSightMedium()
returned a reference into the static state, which the next step rewrites; it now returns a copy
(VolumetricFog.hpp/.cpp; the header documents the main-thread contract). The two callers (the
renderer's drift warning and triFogSight) bind it to a const reference, so they keep working.
If AI ever moves off the main thread, the sight state needs a snapshot handed over (for example
an immutable shared state swapped atomically); FogSightMapInUse is already a shared pointer to an
immutable map.


3. Found on the way: the published drawn medium went stale in classic lighting
-----------------------------------------------------------------------------
Probe evidence (probe_1, before the fix, after triSetLighting "classic"):
  state=classic t=3: Tai=0.9962 drawn=1 Tdrawn=0.9981
  state=classic t=5: Tai=0.9422 drawn=1 Tdrawn=0.9668
The renderer drew no volumetric fog, yet GetDrawnFogMedium still reported the last remastered
frame's medium (the fogMist=0.5 one). Cause: EngineGL33::UpdateFogMedium (which publishes it)
runs only inside the remastered path of UploadLitFrameConstants; the classic early return never
cleared it. AI never reads it (pinned by test a and the contract), so this only misled probes and
the drift guard. Fix: the classic branch of EngineGL33::UploadLitFrameConstants calls
SetDrawnFogMedium(nullptr) (EngineGL33_Lighting.cpp). After (probe_3): state=classic drawn=0 on
every line.


4. In-game probe at fog 0.3 (look_director_optics staging)
---------------------------------------------------------
New test verb triAiSight [observer, target] (GameStateExtTestRender.cpp, registered next to
triFogSight): the observer's real EntityAI::CalcVisibility (line of sight assumed) next to the
classic tactical fog, the size term, AI sight's T between the observer's eye and the target's aim,
and the same line through the drawn medium. fogAi = vis / (classic x size) is the share AI sight
took inside the real visibility.
Probe look_r5_aitest_probe.test.sqf (copy here), Eden 9200,3700, heading 288, 09:30 5 July 1985,
overcast 0.7, fog 0.3 (the optics staging), an east soldier and west soldiers at 126 to 1109 m;

down the valley. Results (probe_3/udcap.log, sheet aitest_probe_fog03.png):
  - Every line, every state: fogAi = Tai to 4 digits, so the real AI visibility carries AI sight.
  - Overhaul (fog drawn): Tai = Tdrawn to 4 digits on all 7 lines (hill: 1.0000 .. 0.9443;
    valley floor: 0.9936 at 124 m, 0.9293 at 255 m). fogMist=0.5: both move to 0.9677 at 1109 m.
  - Post effects off and classic lighting: drawn=0, AI unchanged (only the clock drift above).
  - On the optics hill the eye is 273 m ASL above most of the mist, so T stays near 1 there; the
    valley lines show the mist taking 7% of a man at 255 m. Beyond about 600 m the classic
    tactical fog alone makes vis 0 at fog 0.3 (classic=0 at 756 m), while the drawn picture still
    shows ridges at 1 km: that is the weather part, AI's classic tactical fog, which the critic
    already noted (the mist fixer draws setFog at 0.75 of the classic extinction). Not changed
    here (fog look and AI weather fog belong to MIST and the owner).
  - The soldiers stand behind the near crest in both shots (the probe assumes line of sight), so
    the shots show the air, not the men.


5. Optional leftover: the ground field late after load (not done)
-----------------------------------------------------------------
TerrainHorizonMap::groundColor comes from the async horizon build (UpdateTerrainLighting:
GroundColors on the main thread, then ExpandGroundColors + BuildTerrainHorizonMap on the worker,
about 0.6 s), and the renderer only uploads _groundFieldTex with the whole map, so the wet classes
fall back to the old seam (a = 0 stand-in) until then. Making it ready at load cleanly needs a new
path: run ExpandGroundColors and the three-channel box downsample on the main thread at the island
change (tens of ms), hand the field to the renderer through a new Engine call (for example
SetTerrainGroundField) that uploads only _groundFieldTex, and let the full map replace it. That is
a new engine API across TerrainLighting, Engine.hpp, EngineGL33 and a load-time cost, and a 0.6 s
window after load is hard to verify in a capture; I left it for a round that owns the wet ground.
