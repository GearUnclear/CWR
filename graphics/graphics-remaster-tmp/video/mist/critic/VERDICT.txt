(e) THE FIX (game bug; fix.patch, read and run)
-----------------------------------------------
Correct as far as I can see:
  - xy: cellJ = fract(fogFrame.xy + 0.5 + cell offset) - 0.5 stays in [-0.5, 0.5) of the cell,
    so each cell still covers its whole footprint over time.
  - z: s + fract(fogDepth.w + g_cellJitter + 0.618034 s) stays in [s, s+1): the slice range
    is unchanged; the per-slice turn also decorrelates the column's slices.
  - Uniforms, sequence, history share, reprojection: unchanged. No C++ logic change.
  - fix.patch applies cleanly to graphics-remaster 907906c (git apply --check). mist-1's diff
    of the three fix files equals fix.patch.
  - Unit test run by me: mist-1 PoseidonTests.exe "Volumetric fog: the injection*": 9/9
    assertions pass (sdFrameWide 0.0313 > 0.025; sdPerCell 0.0054 < 0.0078, a ratio of 0.17).
    [fog] tag: 34 test cases, 6461 assertions, all pass. Lead's 17-tag gate log: 347/347.
  - The extra mist (+0.7 to +1.2 levels in the band) is expected, not a defect: with the
    old coherent jitter the column's optical depth fluctuated as a whole, and the average
    of exp(-tau) over a fluctuating tau is larger (Jensen), so the old haze read slightly
    thin. The decorrelated version is closer to the true mean.
Side notes (none blocks):
  - The three per-cell offsets are not independent per axis: fogCellNoise(p + (17,59)) and
    fogCellNoise(p + (83,29)) equal fogCellNoise(p) plus a constant (0.711-0.728 and
    0.178-0.196, checked over the 160x90 grid). Across cells each axis is still well spread,
    which is what kills the sheet, so this is harmless; a cleaner hash per axis would be tidier.
  - Not tested: cells without history (camera cuts, map close, fast mouse turns revealing new
    screen edge) now start from a per-cell offset instead of one coherent offset, so dense
    mist may show cell-size speckle for the first ~10-20 frames after such an event. The
    clip's slow pan shows nothing at the edges (above).
  - The unit test's mirror re-implements the hash in C++ and only checks the depth axis; the
    string pins are what tie it to the real shader. Acceptable, in line with the file's style.
