The Design Loop

Uslu dur! is a total game overhaul of Arma: Cold War Assault, a full rework of the engine source itself. The upstream engine drop is a frozen "locked" release: there is no official Bohemia roadmap, changelog, or CI pipeline in that tree. Everything past that point is ours: this is how we design and build the overhaul, documented under mod-plans/ and guerrilla-mode/. Read all thirteen plans and a single consistent methodology emerges: a repeatable way to take a gameplay idea from hunch to shipped system, whether the work lands in engine C++ or mission SQF.

★ The Five-Step Loop

#StepWhat It Means
1Source-Truth FirstGrep the actual engine source to confirm a capability exists before designing around it. Unconfirmed claims are tagged // VERIFY: until proven.
2Each Layer Where It WinsThis is a total overhaul of the engine source, so C++ is a first-class tool right alongside SQF. Script stays the layer for content, tuning, and fast iteration (edit a file, relaunch); C++ is the layer for new engine/evaluator commands, data plumbing (faction & island descriptors), UI, persistence, and performance. Each plan states which layer earns its keep and why.
3Risk-GatedName the riskiest unknown and its mitigation up front. In Guerrilla Mode, a "Gate-Zero" smoke test proves engine assumptions (framerate, spawn, save/load) before any content is authored.
4Layered ValidationEvery plan ends with the same ladder: unit → integration (Trident/SQF) → a manual in-game playtest, the "money moment."
5Scope EstimateEvery plan closes with a difficulty rating and a time/scope estimate, so ambition stays honest.
FIELD NOTE

The loop is circular: a playtest surfaces a new unknown → you grep the source to understand it → you build the smallest fix in whichever layer fits → you gate the risk → you re-test. Content is never authored ahead of the assumption that supports it, which is why de-hardcoding factions and islands is scheduled before a second island gets built.

FIELD NOTE

Design docs here are living, AI-drafted plans, subject to revision as understanding improves. This project's own Guerrilla Mode master plan took a direction correction on 2026-07-01: the "SQF-only, C++ last resort" framing was retired, and swappable factions/islands were promoted to a launch requirement. Expect this page to keep changing with them.

Phased Roadmap: Guerrilla Mode

The applied case study (mod-plans/13-guerrilla-mode.md) proves the loop end-to-end. It ships in gates:

Gate-Zero: Prove the Riskiest Assumptions Outstanding

60%

Smoke-test framerate, spawn cost, and save/load survival before authoring any content.

Phase 1: MVP "Three Zones" (pure SQF) Code-Complete

100%

Camp / Village / Outpost, capture triggers, garrison spawning, alert state machine, resource economy, recruiting, loot & gear unlocks, a named companion, and save/load. Written, pending a live playtest.

Phase 1.5: De-Hardcoding, Swappable Factions & Islands Planned

0%

A launch requirement for Guerrilla Mode, done while there's still only one island and one faction pair to migrate. Pulls every faction- and island-specific fact (unit rosters, vehicle pools, civ models, zone positions, camp locations) out of scripts and into swappable faction descriptors and per-island data files, so a new game starts by picking the island, the civilian faction, the resistance faction, and the occupying faction. Exit test: the same script core runs on a second island against a different occupier, chosen at game start. Scheduled after the Phase-1 MVP proves the loop and before any content breadth, because retrofitting it later multiplies the cost. Est. ~1-2 weeks.

Phase 2: Vertical Slice Planned

15%

Deepen the economy and persistence into a real progression loop.

Phase 3: Full Mode Planned

5%

Island-wide, zone-by-zone liberation against an escalating EAST occupier.

SmokePestertests/smoke/
PlaytestA human at the controls, the "money moment"Live build
