Under the Hood

Uslu dur! is a total game overhaul of Bohemia Interactive's opened engine source itself (codename Poseidon). We treat that engine as living ground we actively dig into and modify at the source level, adding real engine-side capabilities alongside script-level work. Everything below is described in that light: this is the tech stack our overhaul builds on and modifies, from renderer to asset formats to the SQF virtual machine itself. We're also extending the engine to serve the overhaul's design, including new evaluator commands and data plumbing for swappable factions and islands, and we call that work out explicitly below.

The whole engine lives in engine/Poseidon/ as a set of C++20 static libraries, with a handful of sibling libraries for platform backends. Here is the map, followed by a look at the engine-side work the overhaul itself is adding.

Engine Subsystems (engine/Poseidon/)

GameGame-layer logic sitting on top of the world simulation.
AI (+ AI/Path)Artificial intelligence and pathfinding. The "brain" (AIUnit : AI) is deliberately separate from the "body" (EntityAI), and this is the layer the overhaul's AI mod-plans are actively rewriting, covering target priority, suppression response, flee-to-cover, shared enemy intel, and dynamic morale.
GraphicsRendering front-end, textures, and the graphics-interface abstraction.
AudioSound front-end covering voice, streaming, capture, and mixing.
AssetLoading & caching of models, textures and packed archives (Formats, Addon, Cache, Probes).
UIUser-interface rendering & widgets (incl. Dear ImGui-based dev tooling).
InputKeyboard / mouse / controller input, via SDL3.
NetworkIn-game multiplayer networking (distinct from the master-server service).

SecurityIntegrity / anti-tamper facilities.

SQF EvaluatorThe scripting virtual machine that runs mission SQF/SQS, the language Guerrilla Mode is written in. It's also the surface where our overhaul is landing new commands (see below) instead of treating it as a closed API.

The Foundation Layer

Rather than lean on the standard library, Poseidon ships its own Foundation, with custom containers, strings, a mimalloc-backed memory system, threading, math, and time. The rest of the engine is written against Foundation, which keeps behaviour deterministic and portable across the Windows and Linux Clang builds.

Rendering (PoseidonGL33)

The renderer is an OpenGL 3.3 backend (engine/PoseidonGL33/) reached through a graphics-interface / factory abstraction, so the concrete API is swappable. Windowing, context creation and input come from SDL3; the GL loader is glad. Texture handling lives under Graphics/Textures with a native PAA decoder.

Audio (PoseidonOpenAL)

Sound runs on an OpenAL Soft backend (engine/PoseidonOpenAL/). The engine-side Audio/ tree splits into Core, Streaming, Voice and Capture, covering streamed music/ambience, positional 3D sound, and voice with Opus / Ogg Vorbis codecs. A dummy backend exists for headless/test runs.

The Classic BI Asset Pipeline

Assets are the original Bohemia formats, loaded through Asset/Formats and the standalone PoseidonFormats C-API library:

FormatWhat
.pboPacked archive bundling an addon's files (models, textures, configs, missions).
.p3d3D models (LODs, geometry, named selections).
.paa / .pacTextures (DXT / palettized), decoded natively by the engine.
.rtmKeyframed animations.

PoseidonFormats exposes these over a stable C API, so external tools, notably the Blender addon (apps/tools/BlenderAddon), can import P3D/PAA/RTM directly.

Engine Work For The Overhaul

This is a total overhaul of the engine source itself. C++ changes to Poseidon are a first-class tool here, right alongside SQF mission scripting. When a script workaround is clunky and an engine command is cheap to add, we add the command. The flagship consumer of this is Guerrilla Mode, our persistent open-world insurgency game mode. Its "swappable factions & islands" requirement, meaning island plus civilian/resistance/occupier faction chosen at new-game, is core to the design, and meeting it drives real engine-side work well beyond mission content:

Engine workStatus
enableAI command (inverse of disableAI)Written, needs a compile/run verification pass.
knownTargets <group> command (group-wide known-contacts, vs. single-object knowsAbout)Written, needs a compile/run verification pass.
Evaluator quality-of-life commands (setVariable/getVariable, isNil, nearestObjects, registering doMove, etc.)Planned. Core to de-hardcoding the scripts, still unshipped.
worldLocations-style command exposing per-world town/location dataPlanned, so the territory layer can auto-seed on any island.
Faction & island descriptor data plumbing (roster/vehicle/civ-model/unlock data per faction, per-island data files)Planned design direction. Not yet implemented.
New-game setup flow (island + faction selection)Planned; the engine's existing mission-template wizard is the likely starting point.

These come from the project's own design docs, which we treat as living, AI-drafted plans that get revised as understanding improves. Where a doc says something is written but unverified, we say so here too, rather than claiming it's done.

Build & Toolchain

The build is modern and opinionated: CMake with presets, generated by Ninja, compiled by Clang only (clang-cl on Windows, GNU-driver clang on Linux), with vcpkg in manifest mode for dependencies and ccache for fast rebuilds. Reproducible Linux builds run in Docker against the Steam Runtime (docker/steamrt4). A separate Rust master-server service (mserver/, plus docker/papa-bear-master-service) handles server browsing. This is distinct from the in-game Network subsystem. Integration tests run through the Rust Trident harness (tri).

Notable Dependencies

Resolved through vcpkg, each keeping its own license: SDL3 for windowing/input, OpenAL Soft for audio, Opus / libogg / libvorbis for codecs, FreeType for fonts, curl for networking, cJSON, CLI11, stb, mimalloc as the allocator, enkiTS as the task scheduler, Dear ImGui for dev UI, and spdlog for logging.
