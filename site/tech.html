Under the Hood

Everything on this page is optional reading. If you just want to play, the free Steam demo is one click away. If you're the kind of player who wants to know what's actually running under the game, or you're a modder sizing up whether to build on this, here's the stack.

Uslu dur! runs on Bohemia Interactive's opened engine source (codename Poseidon), which we build from scratch and actively modify, not just script on top of. The whole engine lives in engine/Poseidon/ as a set of C++20 static libraries. Here's the map, followed by the new engine-side work this overhaul is adding on top.

Engine Subsystems (engine/Poseidon/)

The "brain" (AIUnit : AI) is deliberately separate from the "body" (EntityAI), and this is the layer the overhaul's AI mod-plans are actively rewriting, covering target priority, suppression response, flee-to-cover, shared enemy intel, and dynamic morale.
GraphicsRendering front-end, textures, and the graphics-interface abstraction.

SQF EvaluatorThe scripting virtual machine that runs mission SQF/SQS, the language Guerrilla Mode is written in. It's also the surface where our overhaul is landing new commands (see below) instead of treating it as a closed API.

The Foundation Layer

Rather than lean on the standard library, Poseidon ships its own Foundation, with custom containers, strings, a mimalloc-backed memory system, threading, math, and time. The rest of the engine is written against Foundation, which keeps behaviour deterministic and portable across the Windows and Linux Clang builds.

Rendering (PoseidonGL33)

The renderer is an OpenGL 3.3 backend (engine/PoseidonGL33/) reached through a graphics-interface / factory abstraction, so the concrete API is swappable. Windowing, context creation and input come from SDL3; the GL loader is glad. Texture handling lives under Graphics/Textures with a native PAA decoder.

Audio (PoseidonOpenAL)

Sound runs on an OpenAL Soft backend (engine/PoseidonOpenAL/). The engine-side Audio/ tree splits into Core, Streaming, Voice and Capture, covering streamed music/ambience, positional 3D sound, and voice with Opus / Ogg Vorbis codecs. A dummy backend exists for headless/test runs.

The Classic BI Asset Pipeline

Engine Work For The Overhaul

This is a total overhaul of the engine source itself. C++ changes to Poseidon are a first-class tool here, right alongside SQF mission scripting. When a script workaround is clunky and an engine command is cheap to add, we add the command. The flagship consumer of this is Guerrilla Mode, our persistent open-world insurgency game mode. Its "swappable factions & islands" requirement, meaning island plus civilian/resistance/occupier faction chosen at new-game, is core to the design, and meeting it drives real engine-side work well beyond mission content:

Engine workStatus
Native Guerrilla simulation core: ZoneRegistry (territory, capture, fog-of-war), GarrisonCache (officer-first, distance-cached enemy garrisons), AlertMachine (the GREEN/YELLOW/RED FSM), all serializing into saveGameBuilt the biggest engine deliverable of the overhaul so far: the whole Guerrilla loop moved out of mission scripts and into first-class C++ systems, active only when a mission opts in.
enableAI command (inverse of disableAI)Built registered in the engine command table.
knownTargets <group> command (group-wide known-contacts, vs. single-object knowsAbout)Built registered for both groups and objects.
Evaluator quality-of-life commands (setVariable/getVariable, isNil, nearestObjects, compile, setRank, registering doMove)Built all landed in the evaluator, which is what let the campaign scripts drop their old workarounds.
Faction & island descriptor data plumbing (roster/vehicle/civ-model/unlock data per faction, per-island data files)Built factions and islands are swappable data packs now; the campaign core reads them and carries zero hardcoded unit or side names.
New-game setup flow (island + faction selection)Built a native selection screen ships in the engine UI, pictured on the Gameplay Systems page.
worldLocations-style command exposing per-world town/location data as one SQF callPlanned zones already auto-seed towns by reading each world's own name data; a general-purpose command is still on the list.
nearestRoads road-network query (for auto-placing checkpoints, road-cuts and Fireforce landing zones on any island)Planned the one new command the occupation-systems layer needs; not yet built.
Tactical-AI "feel" plans (target priority, suppression response, flee-to-cover, shared enemy intel, dynamic morale)Planned real AI-internals surgery, budgeted as a funded milestone: this is the "asymmetry you feel" in a firefight, not garnish.
Occupation-systems layer (checkpoints/curfews as terrain, closures & reprisals, Protected Villages, Fireforce, pseudo-gangs, trackers, detention, informers)Planned mostly mission scripting over the systems above, plus the one nearestRoads command; the depth that makes the world read as occupied.

These come from the project's own design docs, which we treat as living, AI-drafted plans that get revised as understanding improves. Where something's built and wired in, it says Built; where it's still a plan on paper, it says Planned. We don't round up.

Mods, Factions and Islands

Guerrilla Mode reads its rosters and its maps as data, so third-party content plugs in without touching our templates or the engine. A faction pack is a CfgGuerrillaFactions block in an addon's config that names one order of battle: infantry tiers per war level, role variants, a vehicle ladder, recruit and loot classes, a flag. The engine merges the global table with whatever the island itself declares, island winning on a name clash, so a pack shipped once shows up in the OCCUPIER and RESISTANCE cyclers on every installed island. A faction whose classes aren't in the loaded data is listed greyed out and refused, rather than launching you into substitute bodies.

An island pack is three files: a description.ext holding the zone table and the civilian population, a mission.sqm with one player unit, and a two-line bootstrap into the shared script core. A generator writes all three from any world that has a name list and a road net, seeding towns from the world's own named locations and sampling every elevation off the heightmap, so nobody hand-surveys coordinates. Missing pieces degrade instead of failing: a world with no roads simply has no ambient traffic, a town with no enterable building puts your headquarters cache outdoors.

ToolWhat it checks
mod doctorScans a mod folder's PBOs for known content defects (undefined scope keyword, malformed float literals, model origins above the mesh) and repairs them in place with --fix, keeping the originals.
guerrilla lintLoads a data package plus its mods, merges the faction table, and reports every descriptor key that would be substituted or dropped, per faction, plus the side-twin chain. Exits non-zero when a roster can't field its first tier.
guerrilla scaffoldGenerates a playable island template from one world's config entry and .wrp: town, camp and outpost zones with sampled elevations, a civilian block, and the bootstrap.

A fourth, guerrilla probe, walks a mod's own roster and flags classes that can't actually be built, such as a missing model file or an event handler pointing at a script that isn't there. Full contracts, with worked examples that are themselves test fixtures, live in the repo at arma_CWR/guerrilla-mode/FACTION-PACKS.md and arma_CWR/guerrilla-mode/ISLAND-PACKS.md.

Build & Toolchain

The build is modern and opinionated: CMake with presets, generated by Ninja, compiled by Clang only (clang-cl on Windows, GNU-driver clang on Linux), with vcpkg in manifest mode for dependencies and ccache for fast rebuilds. Reproducible Linux builds run in Docker against the Steam Runtime (docker/steamrt4). A separate Rust master-server service (mserver/, plus docker/papa-bear-master-service) handles server browsing. This is distinct from the in-game Network subsystem. Integration tests run through the Rust Trident harness (tri).

Notable Dependencies

Resolved through vcpkg, each keeping its own license: SDL3 for windowing/input, OpenAL Soft for audio, Opus / libogg / libvorbis for codecs, FreeType for fonts, curl for networking, cJSON, CLI11, stb, mimalloc as the allocator, enkiTS as the task scheduler, Dear ImGui for dev UI, and spdlog for logging.
