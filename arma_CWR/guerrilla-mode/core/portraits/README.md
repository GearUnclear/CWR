# Optional developer portrait comparisons

Dossier photographs are generated by the engine on the player's machine. A
fresh checkout needs no generated catalogue, Python, Trident, or PoseidonTools
to display them. Vanilla photographs are **not committed** to this repository.

The runtime prepares the selected campaign's complete appearance roster before
new-game or saved-game play. It stores opaque 256 by 256 PNGs and dependency
records under `GamePaths::CacheDir()/portraits/`, honoring the existing cache
directory override. The journal receives an opaque identifier and resolves a
texture directly; it never reads this directory or a `gmcore` portrait path.

Use **Game settings: Clear dossier portrait cache** to discard those local
photographs. They are generated again when needed. Missing or unsupported
appearances show "Photograph unavailable". A read-only or full cache disk does
not prevent in-memory photographs from working for the session.

`catalogue.json`, `tools/screenshots/portrait_roster.py`, the developer shoot
missions, and `portrait_process.py` remain optional comparison tools. Their
output is not installed with the core and is not a runtime prerequisite. For
example, from `arma_CWR`:

```text
python tools/screenshots/portrait_roster.py list
python tools/screenshots/portrait_roster.py emit vanilla tools/screenshots/portraits/portrait_vanilla.test.sqf
```

The fixed recipe captures 512 by 512 pixels, reduces them with Lanczos-3 to a
236-pixel photograph, applies the muted warm treatment, and places it on a
256-pixel paper card. The C++ recipe and source-only tests are authoritative;
the optional Python workflow is for comparisons.

These images are local derivatives of player-provided game assets. Generating
them does not change the original assets' licenses or grant redistribution
rights. Do not commit, release, or automatically upload generated portraits.
The core installer excludes this directory, Git source archives exclude it,
and CI's published dependency/compiler caches do not contain runtime captures.

See [implementation and acceptance](../../PORTRAIT_IMPLEMENTATION.md) for the
architecture, validation commands, and measured results.
