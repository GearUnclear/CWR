# Portrait plan acceptance index

This index follows every bullet of the supplied plan, in its original order.
Implementation details, measurements and repeat commands are in
[PORTRAIT_IMPLEMENTATION.md](PORTRAIT_IMPLEMENTATION.md). Evidence below distinguishes
source tests, real game runs and source inspection. Generated game images and local
test logs remain outside the deliverable.

## Rendering and roster

| Plan requirement | Implementation and evidence |
| --- | --- |
| R1. Selected resolved factions; companion/civilian/commander/sniper/progression bodies; deduplicate; exclude unrelated content | `PortraitRoster.cpp` calls the same `ReadLegendCapability` / `ResolveLegendRoles` used by gameplay at every selected faction threshold. `test_legend_appearance.cpp` checks civilian and progression bodies, recorded appearances, deduplication and exclusion of an unrelated faction. Classic and descriptor-selected PLO/IDF cold gates complete 16 and 12 appearances respectively. |
| R2. Shared face validation; preserve rolls and saved faces; prepare selectable and recorded faces | `LegendAppearance` is called by both `LegendRegistry::BindRow` and roster generation. Source tests cover disabled-field semantics, gender, valid saved faces outside the four roll faces and missing saved faces. An invalid fallen face remains unavailable; only the living fallback gets a separate entry. Save/reload lanes compare the exact saved body, face and portrait identifier. |
| R3. Isolated normal character/model/animation/face binding | `PortraitRenderer` constructs an unregistered `Man(type, false, Creation::AppearanceOnly)`, selects `EffectStandStill` and neutral mimic, then checks that the requested face texture actually occupies a model section. Actual dossier texture identifiers match the bound character's body/face. No body-preview or authored portrait is used. |
| R4. Dedicated colour/depth target; fixed pose/camera/light/background; geometry framing | `EngineGL33_Portrait.cpp` allocates a 512-square framebuffer; renderer framing includes posed body and visible proxy vertices. Actual Classic and @LoBo dossiers, including a covered face and helmeted commander, were inspected at 800x600 and 2560x1440. |
| R5. No campaign simulation or shared geometry changes; restore rendering state | Source inspection confirms no `NewVehicle`, AI/group registration, network create, simulation, script initialization or identity roll in the renderer. Private prepared geometry/proxy copies include animation originals and fresh GPU buffers. Source tests check copying and light-reference ownership. The live isolation verb compares copied RNG output, the serialized legend registry, AI groups/unit counts/network IDs, world entity counts, network session state, camera, lights, weather and simulation time before/after capture, including every selected appearance and an initially unprepared body type. A fixed private, scoped RNG handles visual proxy initialization without consuming the campaign stream; appearance-only construction skips supply cargo and unused cloudlet shapes. |
| R6. 512 to opaque 256; 236 photo, paper and muted treatment; fixed colour inputs | `PortraitRecipe.cpp` ports colour treatment and Lanczos reduction; synthetic-pixel tests check dimensions, opacity, orientation, border, deterministic styling and PNG round-trip. Cold cache PNGs are compared across actual window sizes/gamma. The live test changes rain, overcast and time by 12 hours and requires an identical pixel digest. The audit fixed inherited night shader mode and a one-level fog-colour rounding dependency; recipe `dossier-10` invalidates earlier output. |
| R7. Graphics-thread capture; no player external tools | `PortraitService::Advance` is called by the graphics/loading loop. Encoding and writes are synchronous C++ (worker work was optional). Runtime code launches no Python, Trident, PoseidonTools or other process; those tools are used only for development verification. |

## Cache, lifecycle and journal

| Plan requirement | Implementation and evidence |
| --- | --- |
| C1. Service operations, four states and completion revision | `PortraitService.hpp/.cpp` supplies roster/request/find/texture/advance/cancel/release/teardown operations. Source tests exercise deduplication, priority, completion, exceptions and unavailable terminal states; revision drives actual journal refresh. |
| C2. CacheDir/portraits and override; outside installation/save/network | Root construction uses `GamePaths::CacheDir()` and therefore its override. Acceptance runs use isolated profiles, never `gmcore` storage. No portrait fields are added to serialization or network messages. Installer acceptance preserves the external cache. |
| C3. Content/configuration/recipe addressed dependencies and precedence | Renderer records flattened inherited body/face/move/mimic/material configuration and used model/texture/proxy/pose files; the service re-resolves normal asset precedence and hashes file contents, memoizing file hashes within the session. Source tests exercise metadata/content identity. Real override and same-path face-texture edits each regenerate only four affected entries with twelve hits; recipe changes regenerate the roster. Dependency manifests are inspectable beside each PNG. |
| C4. Unique temporary publication; validation; concurrent readers | Creation atomically reserves a unique temporary directory, writes and closes both files, then renames the complete directory. Source tests exercise two independent service writers, dimensions, truncation, invalid opacity and decoding failure on Windows and Linux. Actual two-process cold launches share a cache successfully. An abandoned partial directory is ignored; one corrupted published PNG regenerates exactly once. |
| C5. New/load gate; responsive X/Y progress; cancellation retains completed work | Hooks run after graphics/configuration setup in `WorldInit` and after restored assets/registry in `WorldImpl`, before gameplay resumes. Real cold/warm and cross-process save tests assert all required appearances terminal at the gate. Progress pumps window events and loading-only keyboard edges. Injected buffered Escape cancels pending work, retains the completed entry, and resumes to completion; failure/cancellation paths return through the existing load failure handling. |
| C6. Late queue, open priority, deduplication, placeholder and navigation retention | `guerrilla_portrait_late` requests a supported face outside the roll pool before opening any map, then verifies completion/deduplication and a later recruit's dossier. Source tests check priority. The dossier lane clears in-memory service state, immediately recomposes the open page and verifies its placeholder, then verifies the same section's photograph after queue advancement. C3DHTML navigation is the named section, including continuation-page names; it has no separate dossier scroll/history offset. |
| C7. Service lookup and opaque composition | `GuerrillaJournalPages` requests the recorded appearance; journal view/block structs carry only identifier/status. `JournalCompose` does no filesystem or graphics lookup. `JournalRender` resolves the texture. Source journal tests replace the former mandatory catalogue assertions. |
| C8. Texture-backed HTML with unchanged layout rules | Both `CHTMLContainer::AddImage` overloads use the same sizing helper. Source tests cover dimensions, link/field attributes and null textures; actual dossier tests check image identity and sum laid-out row heights/widths against the page bounds, including the footer. |
| C9. Memory-only fallback, unavailable placeholder, one diagnostic, bounded failures | Generated CPU pixels remain ready when writes fail; real unwritable-root acceptance displays them and recreates GPU textures without writing images. Unsupported binding terminates and deduplicates. The service logs on the single terminal transition, so repeated requests cannot emit repeated diagnostics in a session. Source tests cover exceptions, failure transitions and queue continuation. |
| C10. Dedicated/headless, graphics recreation, teardown and clear action | Preparation bypasses dedicated/dummy renderers; the renderer also rejects explicit late headless requests before constructing a mannequin. Actual dummy campaign and late-request checks render zero portraits. Dossier tests exercise both real texture-bank remount and the engine's full hard graphics-resource reset, rebuilding from retained pixels. Source tests cover teardown/cancel. `portrait_cache_clear` clicks the actual Game settings action and verifies that the next request renders again with zero cache hits. |
